# Документация проекта STEM Game Constructor (`stem_bot`)

## 1. Контекст и Бриф (Заказчик: Команда STEM ЦУ, Евгений Личкин)

### Суть инициативы
Превратить проверенную настольно-цифровую игру **«НейроФауна»** (прошла 3 запуска на Летней Школе STEM) в **переиспользуемый Конструктор игровых систем (аналоговый SDK)** для образовательных мероприятий STEM.

Организатор мероприятия должен иметь возможность:
1. Настроить тему (сеттинг), целевую аудиторию, длительность (обычно 3–5 дней, по 3–4 действия в день) и игровые фазы.
2. Сгенерировать и сбалансировать игровые компоненты (карточки слотов, свойства/перки, клетки поля, цены и характеристики) с автоматической проверкой экономического баланса.
3. Провести гибридную игру через единого Telegram-бота и Telegram Mini App (TWA) в связке с физическим игровым полем.

### Ключевые ограничения и требования из брифа
- **Гибридный формат**: deckbuilding (сборка артефакта/существа), магазин, экономика и расчёты характеристик проходят в Telegram (Бот + Mini App), а перемещение фишек по глобальной карте — в реальности на физическом поле.
- **Тип конкуренции**: гонка по треку прогресса (например, Эволюционная Спираль на 30 клеток) без прямой токсичной конфронтации между командами.
- **Связь с обучением**: игровая валюта (в «НейроФауне» — ДНК) начисляется преподавателями/админами за реальные успехи в образовательных дисциплинах STEM (Science, Technology, Engineering, Mathematics).
- **Первый обязательный объём (MVP Scope)**:
  - Отделение универсального механического ядра от тематического наполнения (минимум 2 механики и 1–2 подключаемых дополнения).
  - Генератор + валидатор баланса (цены, статы, преимущества/недостатки, экономика по дням).
  - Единый Telegram-бот + Mini App:
    - **Игроку (Команде)**: баланс валюты, общий магазин (по дням/фазам), покупка и замена компонентов по слотам, текущая сборка и расчёт итоговых характеристик.
    - **Администратору**: начисление/списание валюты по критериям, управление фазами/днями и лимитами магазина, обзор всех команд и лидерборд, применение эффектов клеток поля, экспорт аналитики.
  - *Не входит в обязательный MVP*: сложный полиграфический дизайн, автоматическая вёрстка печатного комплекта и P2P-торговля между командами.

## 3. Аудит старого проекта (`neurofauna_bot`) — почему переписываем с нуля

Старый бот был написан на Python (`aiogram` + сырой `sqlite3`) под одну конкретную игру и имеет критические архитектурные проблемы:

1. **Жёсткий хардкод темы («Биология / НейроФауна»)**:
   - В `cards_data.py` зашиты 6 конкретных слотов (`head`, `body`, `front`, `back`, `tail`, `special`) и 3 стата (`speed`, `strength`, `survival`) прямо в колонки таблиц БД (`body_cards.speed`, `teams.speed_modifier` и т.д.).
   - В `handlers/shop.py` условия срабатывания свойств захардкожены через `if name == "Молниеносное": ... elif name == "Ядовитое": ...`. Добавить новую тему (например, «Кибер-Дирижабли», «Робототехника», «Колонизация Марса») без переписывания кода невозможно.
2. **Синхронный SQLite внутри асинхронного бота**:
   - Каждый клик по кнопке открывает новое синхронное соединение `sqlite3.connect(DB_PATH)`, блокируя event loop.
   - В `handlers/action_fields.py` таблицы создаются прямо на лету при каждом действии (`ensure_tables()`).
3. **Хранение состояний в оперативной памяти (`MemoryStorage`)**:
   - Любой перезапуск сервера сбрасывает незавершённые диалоги админов и игроков.
4. **Отсутствие мультитенантности (сессий мероприятий)**:
   - В таблице `game_state` зашит `CHECK (id = 1)`. Нельзя параллельно запустить два тестовых прогона или две смены.
5. **Перегруженный кнопочный UI в чате**:
   - Просмотр магазина из 60+ карточек, сравнение статов «до/после» замены детали и админ-управление 10+ командами через бесконечные inline-клавиатуры неудобны. Вынос магазина, конструктора сборки и админ-дашборда в **Telegram Mini App (TWA)** решает эту проблему кардинально.
