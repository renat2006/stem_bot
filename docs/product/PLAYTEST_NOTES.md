# Прогон сценариев: UX и продуктовые заметки

Дата: 2026-10-14. Стенд: локальный сервер + Mini App, чистая смена «НейроФауна», 3 команды, 6 пользователей (ведущий, капитаны и участники) в разных вкладках, dev-идентичности `?as=<id>:<имя>`. Плюс интеграционный прогон образа с настоящим Postgres на сервере.

## Сценарии

| # | Роль | Сценарий | Итог |

| 1 | Ведущий | Пустая смена → создать 3 команды → видны коды входа | ✅ |

## Исправлено по ходу прогона

1. **Критично**: при склейке снимка правила перетирали свежее состояние — интерфейс не обновлялся ни после своих действий, ни по WebSocket.
2. Заголовок dev-идентичности с кириллицей ронял все HTTP-запросы.
3. PGlite-драйвер попадал в прод-бандл статическим импортом — прод-образ не стартовал бы.
4. Пустая версия зависимости в `package.json` — CI упал бы на `npm ci`.
5. Участнику без права покупки показывалось «Купите до 2 карт» → «Предложите карты капитану».
6. «@Алиса» для пользователей без username → просто имя.
7. «Алиса присоединился» → «В команде: Алиса (капитан)».
8. «+5 мин с текущего момента» перезапускал окно → «Продлить на 5 мин».
9. Режим фазы из шаблона («ПО КНОПКЕ») не совпадал с фактом → «ОКНО ПО ТАЙМЕРУ» / «ПО КНОПКЕ ВЕДУЩЕГО».
10. Подпись Telegram жила 1 час, а приложение открыто весь день → 12 часов и понятный текст «закройте и откройте приложение».
11. Локальный запуск с боевым токеном удалял бы вебхук прода → бот в dev стартует только с `BOT_POLLING=true`.
12. Код команды подставляется из `startapp` (QR → Mini App сразу с кодом).

## Точки роста

### Участник
- **Уведомления в Telegram** при событиях своей команды: рынок открыт/закрывается через 2 минуты, предложение капитану, начисление с причинами. Для асинхронных окон («рынок открыт час») без этого игроки пропускают фазы. *P1*
- **Статус своего предложения** у участника: «ждёт / куплено / отклонено». Сейчас после отправки обратной связи нет, пока карта не появится в сборке. *P1*
- **Покупка из входящих** у капитана — без тоста и отмены, в отличие от покупки с рынка. Унифицировать. *P2*
- **Живые события своей команды** — короткий тост и тактильный отклик, когда пришло начисление или капитан что-то купил. Сейчас данные меняются молча. *P1*
- **Капитан на виду**: имя капитана и состав команды на главной. Участник не всегда знает, кому писать. *P2*
- **Главная длинная** на 375 px: блок «Что сделать сейчас» хорош, но рейтинг и прогноз шага уезжают вниз. Свернуть «Характеристики» до одной строки, раскрывать по тапу. *P2*

### Ведущий
- **Пульт — одна длинная лента**. Нужны вкладки «Раунд / Команды / Журнал / Настройки» и липкая панель фазы с таймером. *P1*
- **Предпросмотр хода** перед «Применить шаг ко всем»: таблица «команда: клетка 11 → 15 (+4)». Сейчас подтверждение вслепую. *P1*
- **Отмена начисления**: журнал хранит всё, нужна кнопка «отменить последнее» на 1–2 минуты. *P1*
- **Матрица оценивания** «команды × критерии» для 10 команд за один экран — сейчас разные оценки разным командам требуют нескольких отправок. *P2*
- **QR и ссылка `t.me/<бот>/<app>?startapp=<код>`** у каждой команды для слайда и печати. *P1*
- **Клетки поля событий** (Охота/Катастрофа/Хищник с порогами и откупом) — сейчас ведущий вручную двигает трек и валюту. Правила уже описаны в `docs/legacy/NEUROFAUNA_RULES.md`. *P1*
- **Табло для проектора** — отдельный экран 16:9 из того же потока состояния. *P1*
- **Автопереход фазы по таймеру** (рынок → ход) как опция. Сейчас по истечении таймера рынок закрыт для покупок, но фаза остаётся «рынок», пока ведущий не нажмёт. *P2*

### Продукт и SDK
- **Несколько событий параллельно**: модель данных уже привязана к `event_id`, нужен выбор события по ссылке и права ведущих по событиям. *P1*
- **Live-настройка правил**: копия шаблона хранится в событии, версия правил есть — нужен редактор с диффом и уведомлением участникам. *P1, ядро запроса заказчика*
- **Экспорт журнала смены** (CSV) для методистов и калибровки симулятора баланса. *P2*
- **Политика отсутствующего капитана**: ведущий может переназначить; стоит дать команде самой передать роль. *P2*
- **Сессия длиннее дня**: при многодневной смене открытое приложение всё равно нужно перезапускать раз в день — либо короткоживущий токен сессии после проверки initData. *P2*

## Наблюдения по технике

- Синхронизация ощущается мгновенной: изменение у одного игрока отображается у остальных в пределах ~50 мс (склейка 30 мс + один запрос графа).
- Склейка изменений гасит «шторм» рассылок при массовом начислении.
- Ошибочные действия не увеличивают версию (транзакция откатывается) — клиенты не получают лишних обновлений.
