# Handoff: «Конструкт» — кабинет участника (Telegram Mini App)

## Overview
Конструкт — конструктор игр для STEM-событий. Одна конфигурация игры (модули механик, тема, контент, экономика, расписание) порождает все поверхности: кабинет участника, пульт админа, табло, правила и уведомления бота.

В этом пакете спроектирован и прототипирован **кабинет участника** (C1–C8 из брифа) для двух игр на одной платформе:
- «НейроФауна» — Летняя STEM-школа, 5 дней, механики: сборка + трек + поле событий;
- «Стартап за день» — STEM-конференция, 1 день, 3 асинхронных окна, механики: сборка + трек + заказы, DLC «рынок между командами».

Пульт админа (B*), конструктор (A*) и табло (B7) **ещё не спроектированы**. Их нужно строить в том же визуальном языке и на том же шаблоне модуля (см. `COMPONENTS.md`). Полное ТЗ лежит в `DESIGN_BRIEF.md`.

## About the Design Files
Файлы в `design/` — это **дизайн-референсы в HTML**: прототипы, которые показывают внешний вид и поведение. Это не продакшн-код, копировать его не нужно. Задача — **воссоздать дизайн в целевом стеке**: React + TypeScript + Tailwind CSS v4 + Telegram WebApp SDK (см. §7 брифа). Используйте устоявшиеся паттерны кодовой базы.

Как открыть: `design/*.dc.html` открывается прямо в браузере, рядом должен лежать `support.js`. Вся логика прототипа описана в классе `Component` внутри `<script data-dc-script>`. Расчёты (`calc`, `stepOf`) и данные игр (`G`) перенесены в типизированном виде в `game-config.example.ts`.

## Fidelity
**High-fidelity** для кабинета участника (`participant-prototype-v2`): цвета, типографика, отступы, состояния и взаимодействия финальные. Воссоздавайте их точно.
`directions.dc.html` — это мудборд трёх направлений. Выбрано **1a «Схема»**, остальные оставлены для истории.
`participant-prototype-v1` — предыдущая итерация. Её **не реализовывать**: в ней эмодзи и текстовые расшифровки, v2 их заменяет.

## Global layout (Mini App)
- Ширина 360–430 px, макет нарисован на 375 × 812.
- **Шапка Telegram нативная**: кнопка «Назад» / «Закрыть», заголовок = `game.title`, меню. Внутри страницы её не рисуем: используем `Telegram.WebApp.BackButton`.
- **Нижняя кнопка нативная**: `Telegram.WebApp.MainButton`. На каждом экране одна главная кнопка (таблица ниже). Свои CTA внизу страницы не рисуем.
- Контент — скролл-контейнер. Сверху липкие вкладки (кроме входа и онбординга). Поля 14 px по бокам, 12 px между блоками.
- Bottom sheet и тосты лежат над контентом и под нативной кнопкой. Контейнер скролла создаёт свой stacking context (`isolation:isolate`), иначе липкие вкладки окажутся поверх затемнения.
- Касание ≥ 44 px. Hover-состояний нет. Drag-and-drop не используется.

### C1 Вход
1. Обложка 132 px, radius 16. По умолчанию — полосатая заглушка (`repeating-linear-gradient(135deg, sf2 0 8px, sf 8px 16px)`). Слева снизу: моно-надпись события и название игры 22/600.
2. Три факта сеткой 3×1 (`facts`): число 20 px моно 600 и подпись 11.5 px.
3. Поле «Как вас зовут»: 48 px, radius 12, 16 px.
4. Код команды: 4 ячейки по 56 px, рамка 1.5 px `ac`, 24 px моно 600. Приходит из ссылки, участник его не вводит.
5. Найденная команда: монограмма 44 × 44 на `ac`, название, «капитан @x · N в команде», стопка аватаров по 28 px.
6. Подпись: «Нет кода — капитан создаёт команду и делится кодом.»

### C1 Онбординг (3 карточки)
Сверху прогресс из трёх полос по 4 px. Иллюстрация — блок 300 px на `sf` с точечной сеткой (`radial-gradient(ln 1px, transparent 1px) / 14px`). Под ней заголовок 22/600 и текст 14.5/1.5 цветом `mu`. Ссылка «Пропустить, правила есть во вкладке».
1. «Учитесь — получайте {валюта}»: чек-лист 5 критериев по +2 и итог «+10» с монетой.
2. «Покупайте карты в слоты»: мини-карта (повёрнута на −4°) → три точки → пунктирный слот «старая карта уходит».
3. «Пороги дают шаги»: шкала характеристики из свойства с отметкой порога и блоки шага.
Все тексты, критерии и карта берутся из конфигурации.

### C2 Команда
Блоки сверху вниз:
1. **«Сейчас»** (`sf`, radius 16, padding 14). Кольцо-таймер 66 px (`conic-gradient(warn pct%, sf2 0)`, внутренний круг inset 5, `mm:ss` 15 моно 600, «осталось»). Справа: моно-строка `ДЕНЬ 3/5 · ТОЧКА 3/5 · ПО КНОПКЕ`, заголовок 21/600 «Купите до N карт», подзаголовок «Рынок открыт · дальше {next}». Ниже полоса фаз 4 × (6 px): прошедшие — `fg` с opacity .35, текущая — `warn`, будущие — `sf2`.
2. **Команда**: монограмма 46 px на `ac`, название 16/600, бейдж «N место» + «из M». Справа баланс 32 px моно 600 + монета 20 px, под ним квадраты оставшихся покупок по 14 px (`ac` — свободна, `sf2` с рамкой — использована).
3. **Модуль «Сборка»**. Схема на точечной сетке 12 px, `grid-template-areas` берётся из конфига. В центре `core` на `fg`: объект и три характеристики. Слот — кнопка min-h 82, radius 12: моно-подпись 9.5 px, имя 12.5/500, дельты. Пустой слот: рамка 1.5 px dashed `ac`, текст «пусто · N на рынке», нажатие открывает рынок с фильтром по этому слоту. Под схемой свойство: ромб-контур 12 px `ac`, название и описание.
4. **Модуль «Характеристики»**. Строка = 108 px (глиф, название, значение 24 моно) + шкала. В шапке легенда «порог даёт шаг».
5. **Модуль «Ход»**. Блоки шага, под ними полоса трека: клетки по 8 px (своя — 12 px), пройдено `ac`, прогноз — контур `ac`, остальное `sf2`. Над клетками точки соперников (5 px, `mu`, до 2 на клетку) и своя метка (9 px, `ac`, обводка 2 px `sf`). Подписи «старт · клетка 11 → 15 · финиш 30».
6. **Доп. модуль** («Поле событий» или «Заказы»): заголовок, шкала требуемой характеристики с отметкой (danger → `warn`), чипы условий и наград, бейдж статуса в шапке.

Шапка модуля общая для всех: квадрат 8 px `ac` · название 14/600 · подзаголовок 12 `mu` · «?» (круг 22 px в зоне касания 44 × 36) открывает sheet справки.

### C3 Общий рынок
- Шапка: «Общий рынок» 21/600, «Одни карты для всех N команд». Справа баланс 24 моно + монета 15 и таймер 12 моно `warn`.
- Плашка лимита на `sf2`: квадраты покупок, «осталось N из M», лестница тиров (5 столбиков 4 × (5 + 2i) px, открытые — заливка, закрытые — контур) и «IV — с дня 4».
- Чипы-фильтры с горизонтальным скроллом, 36 px, pill: «Все», слоты рынка, «По карману». Активный чип — `fg` / `bg`.
- Карточка компонента (см. `COMPONENTS.md`). Раскупленная карта полупрозрачная (opacity .5).
- Пустой результат: пунктирный блок «Под фильтр ничего нет» + кнопка «Показать все карты».

### C4 Карточка (bottom sheet, max-h 94%)
1. Подпись `СЛОТ · {СЛОТ}`, имя 22/600, тир, цена 28 моно + монета 20.
2. **Замена**: «СЕЙЧАС» (старая карта, рамка dashed `neg`; если слот пуст — dashed `ln` «пусто») → шеврон → «СТАНЕТ» (рамка 1.5 `ac`).
3. **До/после** по каждой характеристике: глиф, новое значение 22 моно, дельта цветом и знаком, шкала в режиме сравнения. Над шкалами легенда: остаётся / прибавится (штриховка) / уйдёт (пунктир `neg`).
4. **Шаг за ход**: старое значение зачёркнуто, новое 26 моно, бейдж дельты (`warn` при снижении, `pos` при росте). Блоки шага сравниваются со старыми: блок, который перестал работать, — пунктир `warn`, новый — рамка `pos`. Если шаг падает: «Пунктирные блоки перестанут работать: …».
5. Блок блокировки с ромбом `warn` для состояний ниже.

**Состояния главной кнопки** (приоритет сверху вниз):
- раскупили → неактивна «Раскупили» + «Карту купили раньше вас. Последнюю взяла «X»…»;
- лимит → «Лимит покупок исчерпан» + «Куплено 2 из 2…»;
- не хватает → «Не хватает N {валюта}» + подсказка про фильтр «По карману»;
- роль без прав, при этом всё доступно → «Предложить капитану»; капитану уходит сообщение в чат с кнопкой «Купить за N»;
- иначе «Купить за N {валюта}» → покупка.

### C6 Трек
Список команд по позиции: место 15 моно, имя (своя команда — 600 и « · вы», строка на `sf2`), «pos/len», полоса 8 px. Своя полоса `ac`, прогноз — `ac` с opacity .3, чужие — `mu` с opacity .55.

### C8 Правила
Поиск (44 px на `sf2`), плашка версии правил (рамка `ac`: «Версия 4 · 15:58 · рынок продлён до 16:15»), секции по модулям. Каждая секция: заголовок 15/600 и моно-тег модуля справа. Строки на `sf2`: глиф | текст 13 | значение моно. Секции: Шаг за ход, Сборка, Рынок, доп. модуль, «Как получить {валюта}». Все строки генерируются из конфигурации.

## Interactions & Behavior
- **Покупка** (капитан): списание, `purchases + 1`, остаток карты − 1, карта встаёт в слот и вытесняет старую. Возврат на главную, тост ««X» в сборке · −N {валюта}» с кнопкой «Отменить» на 6 с (полоса прогресса 3 px `ac2` уменьшается линейно), сообщение «Покупка» в чат бота, тактильный отклик `HapticFeedback.notificationOccurred('success')`.
- **Отмена**: восстановить снимок (баланс, сборка, покупки, остатки), тост на 2.5 с, сообщение в чат «Покупка отменена». На сервере — компенсирующая операция в журнале.
- **Предложить капитану** (участник): тост «Предложение ушло капитану @x» на 3 с, в чат сообщение с прогнозом шага и кнопками «Купить за N» / «Не сейчас».
- Таймер тикает каждую секунду. Кольцо и полоса обновляются с `transition: 1s linear`.
- Пустой слот → рынок с `filter = slot`.
- «?» → sheet справки модуля. Нажатие на затемнение закрывает любой sheet.
- Анимации короткие (150–250 ms, ease-out) для sheet и тостов. В облегчённом режиме (`prefers-reduced-motion` или слабое устройство) отключаются.
- Тема Telegram: слушать `themeChanged` и переключать набор токенов light/dark (ниже). Цвет темы события накладывается поверх.

## State (участник)
```
screen: 'join'|'onb'|'home'|'market'|'track'|'rules'
onbStep: 0..2; name: string
sel: cardId|null; help: 'build'|'step'|'extra'|null
wallet, purchases, build: Record<slotKey, Card|undefined>, left: Record<cardId, number>
filter: 'all'|slotKey; afford: boolean
toast: {text, canUndo, until, ms}|null; prev: snapshot|null (для отмены)
secs: number (до закрытия окна)
role: 'captain'|'member'
```
Все производные (характеристики, шаг, разбиение шага, эффект карты, рейтинг, тексты правил) считаются чистыми функциями от конфигурации и состояния: `calc`, `stepOf` в `game-config.example.ts`. На сервере те же функции нужны для честного расчёта и симуляции баланса.

Серверные события, на которые экран реагирует в реальном времени: начисление, смена фазы/таймера, покупка другой командой (остаток), изменение правил (новая версия → плашка в «Правилах» + сообщение бота), конфликт покупки (карта ушла, пока открыт sheet → состояние «раскупили»).

## Design Tokens
См. `tokens.css` (Tailwind v4 `@theme` + CSS-переменные) и `tokens.json`.

**Три слоя:**
1. Тема Telegram (light/dark) задаёт `bg, sf, sf2, fg, mu, ln, tg, scrim`. Можно смапить на `themeParams`: `bg_color → bg`, `secondary_bg_color → sf2`, `text_color → fg`, `hint_color → mu`, `section_bg_color → sf`, `header_bg_color → tg`. Значения ниже — фолбэк и эталон.
2. Оболочка: шрифты, радиусы, отступы, семантика `pos / neg / warn`.
3. Тема события: `ac`, `ac2` (парный тон для другой темы), `coin`, цвет и форма глифа каждой характеристики, все названия.

Шрифты: **IBM Plex Sans** (400/500/600/700) и **IBM Plex Mono** (400/500/600), Google Fonts, OFL, кириллица. Глобально `font-variant-numeric: tabular-nums`. Моно используется для чисел, таймеров, подписей слотов и тегов модулей (uppercase, letter-spacing .06–.08em).

Типографическая шкала: 9.5 / 10.5 моно-подписи · 11–12.5 вторичный · 13–14.5 тело · 16–17 имена · 20–22 заголовки экранов · 24–34 ключевые числа (моно 600).
Радиусы: 2 (клетки шкал) · 5–7 (чипы-дельты, бейджи) · 10 (строки) · 12 (кнопки, слоты) · 14–16 (карточки-модули) · 20 (верх sheet) · 99 (фильтры).
Отступы: 2 / 3 / 4 / 6 / 8 / 10 / 12 / 14 / 16 / 18.

## Assets
Растровых ассетов нет. Глифы характеристик, монета, шевроны, чекбоксы и столбики тиров — это CSS-примитивы (`clip-path`, border, conic-gradient), их легко повторить в коде. Обложка события и картинки карт — опциональные слоты темы, по умолчанию полосатая заглушка. Без иллюстраций интерфейс должен выглядеть законченным.
