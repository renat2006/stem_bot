# Игровое ядро (packages/shared)

Справка: правила оригинала — `docs/legacy/NEUROFAUNA_RULES.md` (+ `neurofauna-data.json`), исследования баланса — `docs/research/GAME_DESIGN.md`.

## Принципы
1. **Механика ≠ тема.** Ядро не знает слов «ДНК», «Скорость», «Голова». Всё тематическое — данные `GameTemplate`. Любой `if (name === "...")` в ядре — дефект.
2. **Декларативные правила.** Эффекты клеток поля и перков описываются данными (триггер → условие → эффект), а не текстом `effectText`. Текст — только для отображения и генерируется/пишется рядом.
   - Триггеры: `onTurnStep`, `onCell(cellType)`, `onPurchase`, `onDayStart`.
   - Условия: пороги характеристик (`gte/lte/eq`), позиция в рейтинге, флаги (например, «был штраф в прошлый ход»).
   - Эффекты: `currency ±n`, `track ±n`, `stat ±n`, `cancelPenalty`, `loseCard`, `offerCards(n, slot?)`, `setFlag`.
3. **Чистые функции.** `engine.ts` без I/O, без `Date.now()`/`Math.random()` внутри — случайность и время передаются параметрами (seed/rng), чтобы симуляции и тесты были детерминированы.
4. **Zod — единый источник типов.** Типы = `z.infer`. Сервер валидирует шаблоны той же схемой, что и генератор (Structured Outputs по JSON Schema из Zod: `z.toJSONSchema`).
5. **Минимум две механики.** Требование брифа/заказчика: ядро должно поддерживать как минимум две разные механики (например, «сборка по слотам + гонка по треку» и альтернативную), плюс 1–2 подключаемых дополнения. Новые механики — модулями, а не флагами в одной функции.

## Расчёты (эталон — legacy, см. NEUROFAUNA_RULES.md)
- Статы команды = сумма карт в слотах + активный перк + админ-модификаторы.
- Шаг по треку = базовый шаг + пороговые бонусы характеристик + бонусы карт + бонусы перков + эффект клетки; результат ограничен `[1, trackMax]`.
- Клетки поля — таблица порогов по характеристике (например, Охота по Силе: ≤2 штраф −1 с откупом, 3–4 → +3 валюты, 5–7 → +2 трека и +3 валюты, 8+ → +3 трека и +5 валюты).

## Баланс
- `validateGameBalance` — статические проверки (эффективность стат/цена по дням, покрытие слотов, пустые дни).
- Следующий шаг — **симуляция**: агенты с разными стратегиями проходят смену (дни × действия), сравниваем распределение финишей, долю побед стратегий, приток валюты vs стоимость полной сборки. Целевые метрики и подход — `docs/research/GAME_DESIGN.md`.
- Генератор (ML) никогда не публикует шаблон без прохождения схемы + валидатора + симуляции.

## Тесты (обязательно)
- Любое изменение `engine.ts` — с тестами в `*.test.ts` (vitest, `npm test -w @stem/shared`).
- Для переноса правил legacy — табличные тесты «вход → ожидаемый результат» по данным из `neurofauna-data.json`.
- Пресеты проходят `GameTemplateSchema` и ссылочную целостность (слоты, статы, перки) — тест уже есть.
