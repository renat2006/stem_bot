# ТЗ на дизайн: конструктор игровых систем для STEM-событий (SDK + Telegram-бот)

> Самодостаточный бриф для дизайнера (Claude Design). Интерфейс на русском. Стиль — новый, собственный: не копировать фирменный стиль заказчика, Telegram или других продуктов.

---

## 0. Коротко

Мы делаем **не приложение для одной игры, а конструктор игр**.

Есть проверенная игра «НейроФауна»: её трижды провели на Летней STEM-школе, она работает. Но она намертво привязана к одной теме (биология, эволюция), к одному формату (5 дней, синхронная фаза в конце дня) и вручную сбалансирована за три итерации. Следующие события будут про другие темы, длиться 1, 3 или 5 дней, проходить с другими участниками.

Продукт должен позволять:
1. **Собрать игру под запрос**: организатор описывает событие (тема, аудитория, длительность, сколько раз команды взаимодействуют с игрой) → система предлагает готовую игру из модулей механик, контента и экономики с просчитанным балансом.
2. **Тонко настроить** её до старта: включить и выключить механики, добавить дополнения (DLC), поправить карточки, правила, цены, расписание фаз — и сразу видеть, как это влияет на баланс.
3. **Провести** игру через **один Telegram-бот** (чат + Mini App) для всех ролей: участники тратят валюту и строят свою «сборку», админы начисляют валюту, запускают фазы, видят все команды.
4. **Подстраивать игру прямо во время события**: поменять параметр, открыть рынок на час вместо 15 минут, подключить новый модуль — с предупреждением о последствиях для баланса.

Задача дизайна — сделать эту гибкость **простой**: организатор не геймдизайнер и не программист; админ на событии работает на ходу с телефона; участник за секунды понимает, что у команды есть и что выгодно сделать.

## 1. Проблема (со слов заказчика)

- Механика понятная и проверенная, но **заточена под узкую тему** — сейчас её можно использовать только с биологическим сеттингом.
- **Подготовка ручная**: первая версия — неделя работы с картонными карточками; переход на Telegram-бот сократил подготовку повторного запуска до 20 минут, но только для той же игры.
- **Баланс карточек делали вручную** в три такта: каждая карта уникальна и несёт штраф, чтобы не было «дошёл до неё — и выиграл». Нужен генератор, который просчитывает экономику и создаёт карточки на ходу.
- **Форматы разные**: однодневная конференция, 3-дневное событие, 5-дневная смена; количество «точек взаимодействия» (получить валюту → потратить → сходить) разное — например, 7 за неделю.
- **Тайминг разный**: в прошлый раз всё было сжато в 30 минут в конце дня (рынок 10–15 минут, ход по полю 10–15 минут); но фазы могут быть растянуты (рынок открыт час) или идти асинхронно в течение дня.
- **Аудитория разная**: школьники, студенты, внешние участники.
- **Хочется больше «кирпичиков»**: минимум две разные механики, которые могут чередоваться и меняться, и подключаемые модули-дополнения (например, «карточки природы», «карточки компаньонов»).
- Печатные материалы **генерировать не нужно** — всё должно жить в боте. Физическое поле в аудитории может использоваться, но не обязательно.

## 2. Модель продукта (что проектируем)

```
Библиотека модулей  →  Игра (конфигурация)  →  Событие (запуск)  →  Live-настройка
механики + DLC          тема, механики, контент,    ссылка, команды,      правки по ходу
                        экономика, расписание,      роли, фазы            с пересчётом
                        баланс                                             баланса
```

**Сущности, которые интерфейс должен сделать понятными:**

| Сущность | Что это | Пример |
| :--- | :--- | :--- |
| **Модуль механики** | самостоятельный кирпич правил со своими данными, действиями игрока, действиями админа и виджетами | «Сборка по слотам», «Гонка по треку», «Поле событий», вторая механика (см. §3.2) |
| **Дополнение (DLC)** | модуль, который расширяет другой | «Компаньоны», «Природа и среда», «Рынок между командами» |
| **Тема (контент-пак)** | словарь и образы поверх механик | валюта «ДНК» → «Кредиты», часть «Жало осы» → «HR-отдел», «Эволюционная спираль» → «Путь к IPO» |
| **Контент** | карточки, свойства, события, клетки — генерируются и правятся | 78 карт частей тела по 5 тирам |
| **Экономика** | откуда берётся валюта (критерии оценки учёбы, события) и куда уходит (покупки, откупы, ходы) | 5 критериев дня × 2 валюты; базовая карта стоит 2 |
| **Расписание** | точки взаимодействия по дням и фазы внутри каждой | День 1–5, одна точка в день: начисление → рынок → ход → итоги |
| **Режим фаз** | как идёт фаза: синхронная по кнопке, окно по времени, асинхронно весь день | «Рынок открыт с 16:00 до 17:00» |
| **Баланс** | проверка и симуляция: нет ли доминирующих карт и стратегий, успевает ли экономика | «Стратегия „всё в Силу“ выигрывает в 64% прогонов» |
| **Событие** | конкретный запуск игры: уникальная ссылка в боте, команды, участники, админы | «Зимняя школа, 3 дня, 8 команд» |

## 3. Механики: что уже есть и как расширяется

### 3.1 Базовый набор (из «НейроФауны»)

- **Сборка по слотам.** У команды «объект» из N слотов (существо: голова, туловище, лапы, хвост, особая часть). Каждая карта — в свой слот, несёт +/− к характеристикам (2–4 характеристики, например Скорость, Сила, Выживание) и цену. Новая карта в занятый слот **вытесняет** старую — склада нет. Одно активное **свойство** (пассивный перк с условием).
- **Общий рынок.** Один для всех команд — все видят одно предложение, это создаёт живость. Тиры карт открываются по дням (базовые → усиленные → продвинутые → элитные → легендарные); сильные карты обязательно с минусом. Лимит покупок за точку взаимодействия.
- **Гонка по треку.** Трек N клеток. За точку взаимодействия команда продвигается на 1 + бонусы по порогам характеристик (например, Скорость ≥ 4 → +1).
- **Поле событий.** Команда попадает на клетку (кубик на физическом поле или виртуально), исход зависит от характеристик: ресурс, мутация (выбрать бесплатную карту), охота / катастрофа / хищник (бонус или штраф с возможностью откупа).
- **Начисление за учёбу.** Админы начисляют валюту по критериям учебного дня («цель понятна», «все роли включены», «технический шаг выполнен»…). Участники сами себе ничего начислить не могут.

### 3.2 Расширение (гипотезы — интерфейс должен вмещать любые модули)

- **Вторая механика** (одна из кандидатов): «Заказы» — общий пул заданий с требованиями к характеристикам, выполнение даёт валюту и шаги; «Исследование» — дерево технологий вместо слотов; «Территории» — карта зон, за которые команды соревнуются без прямой атаки. Механики могут **чередоваться по дням** (День 1–2 — сборка, День 3 — заказы).
- **DLC «Компаньоны»**: дополнительный слот-помощник с особым умением.
- **DLC «Природа / среда»**: карта дня меняет правила для всех (например, «Засуха: Выживание ниже 3 → −1 шаг»).
- **DLC «Рынок между командами»**: продажа ненужных деталей другим командам.

Главное для дизайна: **каждый модуль приносит в интерфейс одинаковый набор частей** — секцию настройки в конструкторе, виджет на экране участника, действия админа, строку на табло, абзац правил. Нужно спроектировать этот **шаблон модуля**, чтобы новые механики вставали без переделки интерфейса.

## 4. Роли

| Роль | Где | Главное |
| :--- | :--- | :--- |
| **Организатор / методист** | ноутбук, до события; иногда телефон | собрать игру под запрос за вечер, быть уверенным в балансе, быстро поправить правило |
| **Админ события** (ведущий, ассистенты, преподаватели) | телефон, ходит по залу и к физическому полю; иногда ноутбук | начислить / списать валюту с причиной; открыть и закрыть фазу; увидеть по команде всё сразу («кто вы, что у вас, где вы»); подправить правило по ходу |
| **Капитан / участник** | свой телефон, вокруг команда | понять, что выгодно купить, как изменится сборка, какая сейчас фаза; купить в 2–3 касания |
| **Участник без прав покупки** | свой телефон | видеть состояние команды, рейтинг, правила; предложить покупку капитану |
| **Зал** | проектор | табло: рейтинг, трек, события, таймер фазы |

Участники — от школьников 9–10 класса до студентов и внешних гостей. Регистрация — по уникальной ссылке события в боте: участник указывает имя и присоединяется к команде (или создаёт её по коду).

## 5. Принципы UX

1. **Простое по умолчанию, глубокое по запросу.** Любую игру можно запустить из запроса в 3–4 поля и одной кнопки; тонкая настройка — раскрывается, но не мешает.
2. **Каждое изменение показывает последствия.** Поменял цену, порог или включил модуль → сразу виден эффект на баланс (индикатор, предупреждение, что изменилось в симуляции).
3. **Одна модель — много поверхностей.** Конструктор, бот, табло и правила строятся из одной конфигурации. Если правило изменено — оно меняется везде; участникам приходит уведомление с объяснением.
4. **Каждое число объяснимо.** Шаг, характеристика, цена, исход события раскрываются в расчёт по слагаемым.
5. **Интерфейс знает фазу и режим.** Участник всегда видит: что сейчас можно делать, сколько осталось до закрытия окна, что будет дальше.
6. **Одна главная кнопка на экран** — нативная нижняя кнопка Telegram в Mini App.
7. **Ошибка исправима.** Подтверждение необратимого, отмена последней операции, журнал «кто, что, когда, почему».
8. **На ходу и с расстояния.** Админ работает одной рукой; ключевые цифры участника читаются через плечо капитана.
9. **Учёба первична.** Начисление — это оценка учебной работы по критериям, а не раздача очков.
10. **Честная генерация.** Видно, что сгенерировано и на каких допущениях; без фальшивых процентов и «магии».

## 6. Визуальное направление

Заказчику важнее механика, контент и работающий бот, чем украшения. Поэтому визуальная система должна быть **лёгкой, системной и хорошо переносить любую тему**, а не держаться на дорогих иллюстрациях.

- Предложи 2–3 направления характера (мудборд + ключевой экран), затем развей одно. Ощущение: инженерная точность + игровой азарт; ассоциации — схема, модуль, конструктор, сигнал.
- Рабочее название платформы: предложи 3 варианта.
- **Три слоя оформления:**
  1. тема Telegram пользователя (светлая/тёмная) — фон и текст;
  2. оболочка платформы — типографика, сетка, состояния, иконки интерфейса, движение (неизменны);
  3. тема события — акцентный цвет, иконки и цвета характеристик, названия валюты, объекта, слотов, трека; опционально обложка и картинки карт.
- Тема без иллюстраций — **нормальный режим по умолчанию**: карточки, сборка, трек должны хорошо выглядеть на одних иконках, цифрах и цвете. Иллюстрации — улучшение, а не требование.
- Карточка компонента — главный графический объект: слот, название, цена, характеристики со знаком, тир редкости (не только цветом).
- Шрифт: кириллица + латиница, свободная лицензия, **табличные цифры**.
- Анимации короткие и функциональные; облегчённый режим для слабых Android.

Покажи один экран участника и один экран конструктора минимум в **двух темах** × светлая/тёмная.

## 7. Технические рамки

- **Mini App** (участник, админ на ходу): телефон 360–430 px. Сверху системная шапка Telegram с нативной «Назад», снизу нативная нижняя кнопка (основная + вторичная) — в макетах показать как часть экрана, но не рисовать внутри страницы. Безопасные зоны, полноэкранный режим, светлая и тёмная тема Telegram. Касание ≥ 44 pt, без hover и без drag-and-drop как единственного способа. Доступны тактильный отклик, нативные подтверждения и уведомления в чат бота.
- **Чат бота**: уведомления (начисление с причиной, фаза открылась/закрывается через 10 минут, правило изменено), кнопки быстрого входа в Mini App. Предложи формат сообщений.
- **Конструктор**: веб, десктоп и планшет (от 1024 px) — основной; телефон — для быстрых правок и live-настройки.
- **Табло**: 16:9 для проектора, читается с 10 м.
- Реализация: React + TypeScript + Tailwind CSS v4; дизайн отдаётся токенами и повторяемыми компонентами. Все тексты, числа и названия — переменные из конфигурации игры.

## 8. Экраны

### A. Конструктор игры (приоритет 1)

**A1. Мои игры и события**
- Игры (конфигурации) и события (запуски) раздельно. Пресеты: «НейроФауна (5 дней, эволюция)». Действия: создать по запросу, дублировать, сделать событие из игры.

**A2. Запрос**
- Минимум полей: тема и сюжет (свободный текст), аудитория (школьники / студенты / внешние), длительность (дни), число точек взаимодействия, число команд и размер, режим проведения (короткая сессия по кнопке / окна по времени / асинхронно), дисциплины STEM, есть ли физическое поле.
- Можно начать с пресета и только поменять тему.

**A3. Сборка черновика**
- Честное ожидание по этапам: механики → экономика → контент → расписание → проверка баланса.
- Результат — **обзор игры на одном экране**: выбранные модули и почему, расписание точек взаимодействия, ключевые числа экономики, оценка баланса и предупреждения, пример экрана участника. Кнопки: «Настроить» / «Пересобрать с другими параметрами» / «Запустить событие».

**A4. Модули механик и DLC**
- Каталог модулей: описание «что получат участники», совместимость, сложность для игроков, сколько времени фазы требует.
- Включить/выключить, порядок и **чередование по дням** (визуальный таймлайн), параметры модуля.

**A5. Тема и словарь**
- Названия: валюта, объект сборки, слоты, характеристики, трек, клетки, роли. Иконки и цвета характеристик из библиотеки, акцентный цвет, обложка. Перегенерация названий по теме.

**A6. Контент**
- **Карточки**: таблица (массовая правка цен и характеристик) и карточный вид; фильтры по слоту, тиру, дню; «сгенерировать ещё N сбалансированных карт для слота X»; подсветка слишком сильных и бесполезных карт с объяснением.
- **Свойства и эффекты**: конструктор правила «Когда → Если → То» с автоматической человеческой фразой.
- **События / клетки**: типы, пороги «характеристика → исход», цена откупа.

**A7. Экономика**
- Источники валюты: критерии оценки учёбы с весами, события; траты: цены, лимиты, откупы, дополнительные действия.
- График «ожидаемый доход команды vs стоимость сборки по дням»; предупреждения («полная сборка доступна уже на 2-й день»).

**A8. Расписание и фазы**
- Таймлайн события: дни → точки взаимодействия → фазы (начисление, рынок, ход, итоги). Для каждой фазы — режим (по кнопке / окно с временем / асинхронно весь день) и длительность.
- Шаблоны: «Сессия 30 минут в конце дня», «Рынок открыт весь день», «Однодневная конференция: 3 окна».

**A9. Баланс**
- Общая оценка, метрики симуляции (доля побед стратегий, отрыв лидера, разброс финишей, используемость карт), график дохода. Каждое предупреждение ведёт к месту правки и предлагает исправление.

**A10. Предпросмотр**
- Экран участника и админа на выбранном дне и фазе с тестовыми данными.

**A11. Запуск события**
- Ссылка и QR на событие в боте, коды команд, приглашение админов и роли, проверка готовности.

### B. Пульт админа во время события (Mini App, приоритет 1)

**B1. Дашборд события**
- Текущий день, точка взаимодействия, фаза и её таймер.
- Все команды: валюта, характеристики, позиция, сборка в миниатюре.
- Режим «у поля»: выбрал команду → крупная карточка «кто вы, что у вас, где вы».

**B2. Начисление и списание**
- По критериям или произвольно с обязательной причиной; одной или нескольким командам; отмена в течение нескольких секунд; уведомление команде с причиной.

**B3. Фазы**
- Открыть/закрыть рынок, запустить ход, подвести итоги; задать окно по времени; прогресс «7 из 10 команд сделали покупки».

**B4. Ход и события**
- Для модулей с полем: выбрать команду → клетку → исход по её характеристикам → откуп или выбор → подтверждение.

**B5. Live-настройка**
- Поменять цену, порог, лимит, длительность фазы; включить DLC с завтрашнего дня.
- Превью: что изменится, влияние на баланс, кого затронет. Подтверждение → новая версия правил, уведомление участникам «что поменялось и почему».

**B6. Журнал**
- Все операции и версии правил; отмена; фильтры по команде и админу.

**B7. Табло** (проектор)
- Рейтинг, трек, события, фаза и таймер; раскрытие итогов.

### C. Кабинет участника (Mini App, приоритет 1)

**C1. Вход**
- По ссылке события: имя → создать команду по коду или присоединиться к команде.
- Короткий онбординг (3 карточки), правила генерируются из конфигурации.

**C2. Главная команды**
- **Собирается из виджетов включённых модулей**: сборка, характеристики, прогноз шага, валюта, позиция, задания и т. д.
- Сверху — фаза и что сейчас можно сделать (с таймером окна).

**C3. Общий рынок**
- Одно предложение для всех: видно, что карту купила другая команда, сколько осталось. Фильтры по слоту, характеристике, «по карману». Лимит покупок, баланс.

**C4. Карточка и покупка**
- Превью «до/после» (характеристики, бонусы шага), вытеснение старой карты при занятом слоте, нижняя кнопка «Купить за N». У участника без прав — «Предложить капитану».

**C5. Итоги точки взаимодействия**
- Что произошло: начисление с причинами, исход события, шаги с расшифровкой, новое место.

**C6. Рейтинг и трек.** **C7. Журнал команды.** **C8. Правила** (с поиском и контекстными «?»).

## 9. Обязательные состояния

Пустые, загрузка, нет сети, ошибка с действием, нет прав, фаза закрыта / откроется в …, окно скоро закроется, лимит исчерпан, не хватает валюты, карту купили раньше, конфликт одновременной правки админами, **правила изменены во время события**, модуль выключен / появится с дня N, генерация не удалась частично, баланс с предупреждениями.

## 10. Библиотека компонентов

Карточка модуля (механика / DLC), таймлайн расписания (дни → точки → фазы), переключатель режима фазы, карточка компонента (тиры и состояния), слот сборки, бейдж характеристики (иконка + цвет + значение + дельта), валюта, прогноз шага с расшифровкой, бейдж фазы с таймером, мини-трек, клетка события, строка рейтинга, чек-лист критериев, конструктор правила «Когда → Если → То», таблица порогов, индикатор баланса, предупреждение баланса с действием, «дифф» изменений правил, запись журнала, тост с отменой, превью телефона, нижняя нативная кнопка, bottom sheet, вкладки.

## 11. Тексты

Коротко, на «вы», игровые моменты — с эмоцией. Подготовь тексты для: онбординга, закрытой фазы, нехватки валюты, начисления, изменения правил во время события, сборки черновика, предупреждений баланса, ошибок, пустых состояний, уведомлений в чат бота.

## 12. Чего избегать

- Привязки элементов системы к «НейроФауне»: ДНК, существо, спираль — только как пример темы.
- Интерфейса «под одну механику»: всё, что относится к модулю, — через шаблон модуля.
- Детской мультяшности, «казино»-приёмов, кислотных градиентов.
- Мелких цифр, длинных списков без фильтров, вложенных модалок, информации только цветом.
- Своих кнопок «Назад» и нижних CTA вместо нативных кнопок Telegram.
- «Магии ИИ»: бесконечных спиннеров, фальшивых процентов, скрытых допущений.
- Генерации печатных материалов — не нужна.

3. Карта экранов и навигация для конструктора, пульта админа, кабинета участника и табло.
